# 樱火营地 SakuraCamp

Windows 桌面工具，用于把《饥荒联机版》独立服务器、Steam Workshop Mod 和 SakuraFrp 隧道接成一条可重复的本地开服流程。

## 0.1.10 更新 · 服务器 Mod 管理

- 将“Mod 清单”替换为“Mod 管理”。仅显示服务器 Mod，不显示客户端 Mod；扫描本机 Steam 创意工坊及游戏 mods 目录，包含尚未在当前世界启用的 Mod。
- 每个 Mod 使用独立卡片，展示本地图片、名称、版本、作者、说明、工坊编号和当前启用状态；支持按名称、作者、编号搜索，以及筛选已启用、未启用或文件缺失。
- 卡片按钮可启用或停用当前世界的 Mod。保存到地上及洞穴的 `modoverrides.lua`，下次开服生效；停用保留配置，重新启用时继续使用。运行中锁定修改。
- 每张卡片有齿轮按钮，悬停显示“配置 Mod”。配置窗口读取 Mod 作者提供的配置项、提示、默认值及可选值，支持搜索、恢复默认值、保存和取消。可应用到地上与洞穴，也可单独配置某个世界。地上、洞穴不同值默认保持各自设置，只写入改动的选项。
- 保留复制朋友同步清单、查看版本、文件缺失提示和打开工坊页面。同步清单只列出当前世界启用的服务器 Mod，并包含作者、版本和工坊链接。
- 修改前备份两份世界 Mod 配置，保留未知 Mod、旧配置项和各世界差异；检测到外部改动则要求刷新，双世界写入中途失败会尝试恢复原文件。备份位于 `%LOCALAPPDATA%\SakuraCamp\backups\mod-configs`。
- 配置元数据使用不提供文件、网络、CLR 或模块加载能力的受限 Lua 环境读取，可解析函数、循环生成的选项。无法解析的 Mod 会显示原因并暂停启用或配置。读取本机 Mod 图片，不在发布包内分发第三方 Mod 美术与源码。

使用：关闭旧版工具 → 运行 0.1.10 → 选择世界 → 打开“Mod 管理” → 按需启用、停用或点击齿轮配置 → 一键开服。下载或更新 Mod 仍由 Steam 完成，下载后点“刷新本机 Mod”。已有配置自动读取，无需重新选择全部 Mod。

依赖：MoonSharp 2.0.0，用于读取 Lua 元数据；第三方许可见 `THIRD-PARTY-NOTICES.txt`。

## 0.1.9 更新

- 一键开服优先通过已安装的樱花官方服务控制当前世界的通道开关，直接同步到官方客户端。刷新通道列表、核对账号对应的配置，等待两个开关均打开且运行中，再通过官方 API 核验在线，最后启动世界。仅在没有官方服务时使用独立 frpc。
- 保存关服先保存世界，再关闭本次由工具打开的开关；原本已经打开的通道保留。启动失败会回退本次打开的开关，回退失败保留管理状态以便重试。
- 玩家表格改为独立卡片，显示角色头像、中文角色名、Klei ID、所在世界，以及实时生命、饥饿、理智数值和进度条。头像从本机游戏读取，不在发布包中分发游戏美术资源；Mod 角色使用通用头像。
- 玩家网络数据按实际游戏接口显示：若有毫秒值则显示延迟，通常游戏只提供 `netscore`，此时显示与游戏一致的网络质量等级。不会用节点 ICMP 或全局主机延迟冒充每位玩家的延迟。当前未增加客户端监测 Mod，不能承诺每位玩家都有毫秒值。
- 保留每秒自动状态查询，不设立即刷新按钮。卡片按玩家 ID 更新，避免每秒重建整个列表。选角、幽灵和缺少组件的角色不伪造三维数值。

使用时关闭旧版工具，运行 0.1.9，沿用原来的访问密钥和世界方案。官方客户端需登录同一个樱花账号；不必手动开启通道。通道开关操作和在线核验会记录在本工具的“樱花通道日志”，官方客户端也会记录实际连接日志。

以下为历史版本记录，其旧版操作方式以以上 0.1.9 说明为准。

## 0.1.8 更新

- 服务器状态改为每秒自动更新，移除“立即刷新”按钮；节点 ICMP 探测独立运行，不阻塞玩家和资源数据。
- 一键开服在独立 frpc 的两条启动信号后，还会通过官方接口确认所选通道全部在线，再启动世界。核验失败会停止本次穿透进程并阻止世界启动。
- 运行中每 10 秒复核通道的官方在线状态，在顶部卡片和服务器状态页分别显示地上、洞穴在线/离线结果；接口失败显示待核验，不继续声称在线。
- “日志与诊断”新增独立的樱花通道日志，避免被大量游戏启动日志挤掉，同时脱敏保存到 `%LOCALAPPDATA%\SakuraCamp\logs\tunnels-*.log`。本工具使用独立 frpc，日志不会出现在樱花启动器的守护进程日志中。

## 0.1.7 更新

- 一键开服固定执行“启动当前世界的樱花通道 → 等待通道分别就绪 → 启动世界”，移除手动/自动模式切换。不会再因旧方案的 `AutomaticTunnels=false` 只启动游戏。
- 自动恢复保存的地上/洞穴编号；编号缺失时按当前世界的创建标识或唯一匹配的旧地址恢复。缺少访问密钥、通道不完整或不可用时阻止开服并提示原因。
- 保存关服仍会先保存世界，再停止工具启动的通道。由工具运行的独立版 frpc 与樱花客户端自己的开关互相独立，通道在线状态以实际连接及官方接口为准。
- 基于 0.1.5 的 UI 及 0.1.6 的实时服务器状态页继续更新。

## 0.1.6 更新

基于用户提供的 0.1.5 UI 优化版继续更新。

- 自动连接模式与地上/洞穴隧道编号按世界保存；旧方案含隧道编号时自动恢复为自动模式。开服时重新读取并恢复所选隧道，再运行官方独立版 frpc，无需在樱花客户端手动开启。
- 等待两条不同通道分别报告启动成功后才启动含洞穴的世界。同一条通道反复重连不会被误判为两条已就绪。保存关服后自动关闭工具启动的 frpc。
- 新增“服务器状态”页，每 5 秒通过服务器控制台只读查询地上和洞穴，显示在线玩家、角色、Klei ID、所在世界、游戏提供的玩家延迟、天数、季节、暂停状态、运行时长、CPU 与内存。
- 本机到樱花节点的 ICMP 延迟每 15 秒探测一次，单独标明来源；节点未响应 ICMP 不代表 UDP 通道故障。玩家延迟缺失时显示“游戏未提供”，查询超时显示数据不完整，不会误报无人在线。
- 不安装监控 Mod，不修改第三方 Lua 或地图。监控回包不加入工具导出的诊断日志。



## 0.1.4 更新

- 修复创建请求结果不明确后一直无法重试的问题。新增“检查并恢复创建”：重新读取官方隧道列表；若待确认隧道缺失，用户核对官方面板并确认后，再次读取列表并解除待确认状态。
- 找到已有隧道时保留记录和原节点；没有相关隧道时解除节点限制，允许重新选择节点。恢复检查不会创建、删除或编辑远程隧道。
- 解析官方 JSON 错误代码和具体原因。即使 HTTP 状态为 500，明确的权限、参数等 4xx 业务拒绝也不会继续标为待确认；网络超时和不明确的服务错误仍保留待确认记录。
- 保留原归属标识，避免恢复时丢失对延迟出现隧道的识别能力。

## 0.1.3 更新

- 无隧道账号可在工具内输入樱花访问密钥，选择联机用途和节点，点击“为当前世界创建隧道”。工具通过官方 API 创建同节点 UDP 隧道，远程端口自动分配，再将本地端口对齐。含洞穴世界创建两条，仅地上世界创建一条。
- 节点列表排除满载、离线和不支持 UDP 的节点，展示 VIP 要求；公开招募用途仅显示平台允许公开游戏的节点。账号仍须满足官方认证、权限和隧道额度要求。
- 隧道归属标识及待确认请求在提交前保存。部分成功时保留已创建隧道，再次点击会尝试恢复和补齐；若请求结果不明确且列表尚未显示，则暂停重复创建并提示核对。
- 创建成功后自动选中隧道、生成连接地址并保存当前世界方案，不影响已有 Mod、密码和存档。

## 0.1.1 更新

自动模式现在同时读取官方 `/tunnels` 和 `/nodes` 接口，将所选节点的 `host` 与隧道远程端口组合成连接地址。选中地上、洞穴隧道后自动填入，无需手动输入或勾选同节点确认；同节点、UDP 和端口检查由程序完成。每个世界的隧道编号会随联机方案保存，重新读取后恢复选择。节点域名缺失时给出明确提示，不猜测地址。手动模式保持可编辑。

## 0.1.2 更新

- 自动模式改用官方独立版 frpc，不再自动选择启动器专用版本。首次缺少独立版时从官方 API 获取下载地址，核对官方大小和校验值并检测命令行功能；“世界与环境”也提供下载按钮。
- 中文 Windows 用户目录使用游戏原生 `APP:Klei/` 存储别名，避免路径参数在游戏端被错误解码后误报写入权限失败。
- 穿透就绪后才启动世界；穿透失败时直接显示退出码和最近的脱敏输出。
- 樱花密钥通过官方支持的 `NATFRP_TOKEN` / `NATFRP_TARGET` 环境变量传递，不再写到进程命令行。

## 解决的问题

- 自动发现 `Documents\Klei\DoNotStarveTogether` 下的账号存档和 `Master` / `Caves` 世界。
- 在改端口前创建完整备份，只修改对应世界的 `[NETWORK] server_port`。
- 复用世界已有密码、Klei `cluster_token.txt` 和 `modoverrides.lua`；展示 Mod 名称、编号、版本和工坊链接。
- 通过 SakuraFrp 官方 API 创建或读取隧道，一键开服按当前世界的隧道 ID 控制官方客户端通道，或在未安装官方服务时启动独立 `frpc.exe`。
- 启动地上和洞穴独立服务器，等待真实日志就绪信号；关服发送 `c_shutdown(true)`，保存超时不强制结束游戏进程。
- 导入朋友的 `client_log.txt`，在展示前隐藏已知密码、Klei 令牌和樱花访问密钥。

## 构建和运行

需要 Windows 10/11、.NET 10 SDK 和 Steam。开发构建：

```powershell
dotnet build SakuraCamp.sln -c Release
dotnet run --project src/SakuraCamp.Desktop -c Release
```

生成单文件 Windows 包：

```powershell
dotnet publish src/SakuraCamp.Desktop/SakuraCamp.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o outputs/win-x64
```

## 第一次使用

1. 在游戏中创建世界并退出到主菜单，让 `cluster.ini`、`Master` 和 `Caves` 存档完整生成。
2. 在 Klei 服务器页面创建令牌，把它放在世界目录的 `cluster_token.txt`；工具也可以在“世界与环境”页保存令牌。
3. 输入樱花访问密钥。没有隧道时选择“朋友私下联机”或“公开招募服务器”，点击“读取可用节点”，选择适合的节点，再点“为当前世界创建隧道”。创建成功后地址和方案自动保存。有隧道时点“读取已有隧道”，选择地上与洞穴。
4. 点“检查开服条件”，确认地上与洞穴为同节点的不同 UDP 隧道，本地地址为 `127.0.0.1`，本地端口与远程端口一致。
5. 点“一键开服”，程序自动启动通道，通道就绪后再启动世界。朋友订阅 Mod 后，使用“复制朋友连接命令”的结果加入。

勾选记住密钥后，访问密钥使用 Windows DPAPI 加密保存在当前用户的 LocalAppData；源码、日志和世界备份不会写入樱花访问密钥。世界备份包含游戏运行所需的 Klei 令牌和世界密码，请勿公开上传。点击创建按钮会新增远程隧道，并可能对齐工具为此世界创建的隧道本地端口；不会删除、迁移或修改无关隧道。没有官方服务时使用独立 `frpc.exe`，密钥经子进程环境变量传入；使用官方服务时不读取或修改其凭证配置。本机高权限进程仍可能读取进程内存或环境。樱花访问密钥与 Klei 服务器令牌是两种不同凭证，首次开服仍需准备 Klei 令牌。

创建中断后请保留本机设置，选回原节点重试。若提示请求结果不明确，而官方面板没有对应隧道，点击“检查并恢复创建”。程序会重新读取列表；按提示核对同一账号的官方面板、确认上次请求已结束，再确认解除待确认状态。恢复完成后重新点击创建；没有相关隧道时也可更换节点。若请求还在处理中或列表尚未同步，过早确认可能重复创建，因此不要清空配置后反复提交。

## SakuraFrp 使用边界

SakuraFrp API 对公开游戏服务器有节点限制：公开服务器应使用平台标记为专用/“多线”的节点。小范围熟人联机按平台规则选择合适节点。工具不会绕过实名认证、账户限制或平台的节点策略；请在发布服务器地址前阅读 SakuraFrp 当前规则。

## 安全和存档

- 工具不会执行第三方 Lua，只解析 `modoverrides.lua` 和 `modinfo.lua` 的文本。
- 启动前完整备份世界，默认在 `%LOCALAPPDATA%\SakuraCamp\backups`。
- 朋友连接命令包含服务器密码，请通过私下渠道发送。
- 关闭工具时，如果服务器仍在运行，会先请求保存退出；超时不会强杀服务器。需要继续操作时查看“日志与诊断”。

## 0.1 版本边界

当前版本导入已有世界，不内置地图生成、SteamCMD 安装/更新、Mod 自动修复或远程多人管理。服务器运行期间请保持工具运行；不要用游戏内“创建世界”同时启动同一存档。仅支持常见 Master/Caves 双世界和单地上世界。

已验证模拟服务器的启动/退出、真实本机安装和存档的只读发现、四页 UI 及本机密钥加密。用户已确认 0.1.2 能成功开服。新增创建和恢复流程使用模拟官方 API 验证，未对用户真实账号新增隧道，也未验证新账号的外网端到端连接。

## 验证

`tests/SakuraCamp.Tests` 是无网络、无真实存档副作用的回归测试，覆盖配置分区修改、端口和端点校验、令牌/日志脱敏、Mod 发现、完整备份、两世界生命周期、部分启动失败和慢速保存，以及隧道创建、随机端口对齐、部分成功续建、响应丢失防重复和无关隧道保护。另有 `--smoke-output <目录>` UI 冒烟模式，会打开四个页面、保存截图、验证 DPAPI 往返、地址自动填充和创建节点筛选。

```powershell
dotnet run --project tests/SakuraCamp.Tests -c Release
dotnet run --project src/SakuraCamp.Desktop -c Release -- --smoke-output work/ui-smoke
```
