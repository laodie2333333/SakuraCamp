# 樱火营地 SakuraCamp

Windows 桌面工具，用于管理《饥荒联机版》本地独立服务器、服务器 Mod 和 SakuraFrp 地上/洞穴隧道。当前版本 **0.3.3**，沿用 0.1.5 的 UI 基线增量开发。

## 当前使用流程

1. 在游戏中生成世界后退出，运行程序，在“世界总览”选择世界卡片。
2. 进入“联机设置”，填写樱花访问密钥并读取节点。选择节点时立即为当前世界创建、绑定地上和洞穴隧道；若已有本程序创建的旧通道，先删除旧通道，再创建所选节点的新通道。填写科雷服务器令牌，服务器密码可选，再点“保存联机设置”。仅地上世界只创建地上通道。
3. 已保存的访问密钥、科雷令牌和密码以圆点显示；当前世界的节点恢复显示，无需因框里没有明文而重新填写。旧节点只有编号时先显示已保存节点，联网后补全名称。
4. 在“世界规则”分别选择主世界、洞穴，按分类或搜索修改规则并保存；下次开服生效。已有存档未提供明确值时显示“沿用存档”，不会误显示成默认设置。主世界控制的全局规则不在洞穴中重复编辑。
5. 在“Mod 管理”选择启用的服务器 Mod，点击齿轮配置。新增与删除由程序自动识别；新下载的 Mod 不会自动启用。可复制已启用 Mod 清单给朋友。
6. 回到“联机设置”点击一键开服，程序先保存未提交的规则修改，启动并核验樱花通道，再启动地上和洞穴。通道失败时阻止开服。开服成功保持当前页面，可直接复制连接命令分享给朋友；关服使用“保存关服”。

各页导航固定在左上角，开服等待期间可切页、查看日志与复制连接命令。服务器状态每秒更新。Mod 卡片仅齿轮有“配置 Mod”提示；错误不会自动切走当前页面。

导航顺序：世界总览 → 联机设置 → 世界规则 → Mod 管理 → 服务器状态 → 文件目录 → 日志与诊断。背景使用磨砂透明，能透出后方窗口的模糊色彩，文字与卡片保持清晰；拖动和缩放时持续保持半透明和模糊；系统不支持或启用高对比度时回退为暗色背景。

世界规则搜索支持中文输入法组词，确认文字并停止输入约 100 毫秒后自动筛选；卡片按可视区域创建，滚动与筛选保留未保存的选项。世界规则读取本机游戏资源、原版图标和中文翻译，每张规则卡片显示对应图片，支持游戏提供的规则选项，不包含地图生成参数。保存前备份到 `%LOCALAPPDATA%\SakuraCamp\backups\world-rules`，只写入改动项，保留其他规则、原地图定义、Mod 配置与存档。运行期间锁定编辑；外部文件改动会阻止覆盖，使用“重新读取”更新。使用自定义规则预设覆盖的特殊文件会提示先核对，不猜测实际预设值。

更换节点前先保存关服。在下拉框选择新节点就会立即执行，不需要再次点击保存；换好后重新复制连接命令给朋友。恢复已保存节点、切换世界或读取节点列表不会触发删除，同一节点继续使用已有通道。若中途失败，使用“继续配置节点”重试；请求结果待确认时先通过恢复入口核对，再继续。旧通道已删除时原地址无法继续使用，配置未完成会阻止开服。

## 构建和运行

需要 Windows 10/11、.NET 10 SDK 和 Steam。

```powershell
dotnet build SakuraCamp.sln -c Release
dotnet run --project src/SakuraCamp.Desktop -c Release
dotnet run --project tests/SakuraCamp.Tests -c Release
dotnet run --project tests/SakuraCamp.Desktop.Tests -c Release
```

生成无需安装 .NET 的 Windows x64 单文件包：

```powershell
dotnet publish src/SakuraCamp.Desktop/SakuraCamp.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o outputs/win-x64
```

## 存档与凭证

- 启动前备份世界；修改 Mod 前备份原配置。默认备份位于 `%LOCALAPPDATA%\SakuraCamp\backups`。
- 樱花密钥使用当前 Windows 用户的 DPAPI 加密保存。科雷令牌仍由游戏从各世界的 `cluster_token.txt` 读取，界面以圆点显示；不会上传到樱花。
- 世界备份包含科雷令牌和密码，连接命令包含世界密码。分享前注意内容，诊断日志会隐藏已知凭证。
- 使用受限 Lua 环境读取本地 Mod 元数据与配置，限制执行时间，不开放文件、网络和 CLR；修改时保留未知设置、其他 Mod 和未改动的世界差异。第三方许可见 `THIRD-PARTY-NOTICES.txt`。
- 有官方樱花服务时控制当前世界的通道开关；没有官方服务时使用独立 frpc。保存关服后只停止本次由程序打开的通道，保留原本已运行的通道。
- 创建中断时保留归属与待确认记录，使用恢复入口核对后继续；不修改无关隧道。节点使用仍受樱花官方认证、权限、额度和公开游戏规则约束。

## 范围和验证

支持导入已有的单地上或 Master/Caves 世界，暂不包含地图生成、SteamCMD 安装更新或远程多人管理。服务器运行期间保持工具运行，不要让游戏同时启动同一存档。保存超时不会强制终止服务器。

核心测试使用临时目录和模拟 API。`--smoke-output <目录>` 可检查七页布局、世界规则、Mod 操作、设置回填和界面截图；不会启动用户的世界或操作真实樱花账号。玩家延迟按游戏实际提供的数据展示，没有毫秒值时显示网络质量等级。

## 0.3.3 更新 · 图片异常导致退出修复

- 修复不支持的 KTEX 图片压缩格式导致程序退出的问题。原解码器抛出的 InvalidDataException 没有被 IOException 捕获；现在角色头像、Mod 图标和世界规则图标统一处理可恢复的图片异常，不弹出阻断窗口，不中断后续界面初始化。
- 角色头像读取失败时使用占位头像；规则图标失败时使用文字占位，规则仍可读取和编辑。损坏图片包同样降级处理，单个规则图集失败不影响其他图集。
- Mod 图标不支持、损坏或预览图损坏时，继续尝试其他本地预览图；均不可用时显示卡片文字占位，不影响 Mod 清单和配置读取。
- 图片失败详情写入日志，可继续在“日志与诊断”导出脱敏日志。提示包含 KTEX 压缩格式编号；当前仍只解码 DXT5，其他格式显示占位，不将未知格式当作 DXT5 读取。
- 保留 0.3.2 的新 Logo、0.3.1 的规则卡片性能优化及现有功能。

验证：17 项桌面图片专项检查通过，覆盖不支持格式、截断纹理、损坏 ZIP、有效 DXT5 像素、Mod 多级预览图回退、规则文字占位，以及真实窗口 Loaded 初始化继续完成、导航响应和诊断缓冲保留。207 项核心检查通过，Release 构建无警告或错误。异常场景使用隔离的模拟资源，未取得反馈玩家的原始图片包，不能据此判断其资源为何采用其他格式；未改动用户存档或操作真实通道。

- 创建成功后自动选中隧道、生成连接地址并保存当前世界方案，不影响已有 Mod、密码和存档。

## 0.1.2 更新

- 自动模式改用官方独立版 frpc，不再自动选择启动器专用版本。首次缺少独立版时从官方 API 获取下载地址，核对官方大小和校验值并检测命令行功能；“世界与环境”也提供下载按钮。
- 中文 Windows 用户目录使用游戏原生 `APP:Klei/` 存储别名，避免路径参数在游戏端被错误解码后误报写入权限失败。
- 穿透就绪后才启动世界；穿透失败时直接显示退出码和最近的脱敏输出。
- 樱花密钥通过官方支持的 `NATFRP_TOKEN` / `NATFRP_TARGET` 环境变量传递，不再写到进程命令行。

## 0.1.1 更新

自动模式现在同时读取官方 `/tunnels` 和 `/nodes` 接口，将所选节点的 `host` 与隧道远程端口组合成连接地址。选中地上、洞穴隧道后自动填入，无需手动输入或勾选同节点确认；同节点、UDP 和端口检查由程序完成。每个世界的隧道编号会随联机方案保存，重新读取后恢复选择。节点域名缺失时给出明确提示，不猜测地址。手动模式保持可编辑。
